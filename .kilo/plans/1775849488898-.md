# Muapi Integration Plan (Superpowers Workflow)

## Goal
Integrate `muapi` into the app as a first-class creation flow that follows a **brainstorm -> plan -> generate** Superpowers workflow, not a direct generate-first workflow.

## Current State (Repo Findings)
- App routing is centralized in `src/App.tsx` with separate create pages per mode.
- Create mode entry cards are defined in `src/pages/CreateHubPage.tsx`.
- Shared create workflow state is managed by `useClipCreation` in `src/hooks/useClipCreation.ts`.
- Prompt creation and generation are orchestrated in `src/lib/clips.ts` and `src/lib/promptEngine.ts`.
- Types and option unions are centralized in `src/lib/types.ts` and defaults in `src/lib/constants.ts`.
- The UI already has a `planning` status state, but it is currently technical ("Planning prompt...") rather than user-visible ideation/planning steps.

## Product Direction (Superpowers Style)
`muapi` should be a guided ideation feature with explicit planning artifacts before generation:
1. **Brainstorm**: collect idea, objective, audience, constraints.
2. **Plan**: produce structured strategy (angle options, hooks, risks, recommended direction).
3. **Generate**: convert accepted plan to prompt payload and create clip(s).

## Proposed UX Shape
### A) New Creation Mode
- Add `muapi` as a new card in Create Hub and as a route (e.g. `/create/muapi`).
- New page `CreateMuapiPage` using existing wizard shell patterns (`PageHeader`, `CreationWizard`, `GenerateStep`), but with new early steps:
  - Step 1: Brainstorm
  - Step 2: Plan
  - Step 3: Scene/Style mapping
  - Step 4: Generate

### B) New Planning-Focused UI Components
- `BrainstormStep`: freeform concept + structured fields (goal, audience, tone, constraints, must-include, avoid).
- `PlanStep`: display multiple strategies + recommended strategy + editable plan summary.
- `PlanSummaryCard`: artifact shown in Generate step to preserve user confidence and traceability.

### C) Superpowers Guardrails
- Prevent direct generation from empty brainstorming state.
- Require either:
  - accepted recommendation, or
  - manually selected strategy before generate action is enabled.
- Surface assumptions and unknowns in Plan step so users can quickly revise.

## Prompt/Backend Integration Plan (Do Both)
## Track A: Zero-Contract-Change Path (First)
Use current API contracts exactly as-is to ship quickly and safely:
- No required backend schema changes for MVP.
- Map muapi planning outputs into existing fields already sent to `/functions/v1/build-prompt`:
  - `topic`
  - `angle_prompt`
  - `interview_style`
  - `energy_level`
  - `scene_type`
  - `city_style`
  - `speech_script`
  - optional mode-specific style fields
- Keep `/functions/v1/generate-video` payload unchanged.
- Result: planning quality improves while using today’s stable generate pipeline.

## Track B: Optional Metadata Enrichment (Second)
Add structured muapi metadata for traceability and quality tuning (optional but recommended):
- Extend `CreateClipOptions` with optional `muapi` fields:
  - brainstorm input
  - selected strategy
  - finalized plan summary
  - realism target (cinematic/human-first)
- Forward these as optional fields in `buildPromptFromBackend` request body.
- Backend may use metadata to improve prompt precision without changing generation endpoint behavior.

## Prompt Builder (`src/lib/promptEngine.ts`)
- Add a muapi transformation path that compiles plan artifacts into provider-ready prompt directives.
- Preserve existing hardening (`negative_prompt`, safety/sanitization) and existing generation flow.

## Backend Compatibility and Rollout
- MVP: backend support for `video_type: 'muapi'` is optional if mapped to existing supported prompt fields.
- Enhanced phase: add explicit backend handling for muapi metadata.
- If metadata is unsupported, degrade gracefully by ignoring optional fields and proceeding with existing mapping.

## Routing and Navigation Changes
- `src/App.tsx`
  - add lazy import for `CreateMuapiPage`
  - add route `/create/muapi`
- `src/components/AppLayout/AppShell.tsx`
  - add page title mapping for `/create/muapi`
- `src/pages/CreateHubPage.tsx`
  - add Muapi card with label/subtitle reflecting planning-first workflow

## Hook and State Management Changes
- Extend `useClipCreation` minimally for shared fields; keep muapi planning state in page-local reducer to avoid bloating generic hook.
- Add explicit state machine in `CreateMuapiPage`:
  - `drafting_brainstorm`
  - `planning_options`
  - `plan_selected`
  - `ready_to_generate`
- Map existing `status='planning'` message to richer copy for muapi path (e.g. planning strategy vs prompt compilation).

## Validation Rules
- Brainstorm required: concept + objective.
- Plan required: at least one selected or edited strategy.
- Generate required: finalized plan summary and mapped scene/style fields.
- Reuse `validatePreGeneration` for global clip checks; add muapi-specific prechecks before calling `generateClip`.

## Cinematic + Human-Realism Quality Guardrails (Priority)
Goal: ensure prompts produce the right video type with strong cinematic realism, especially for subway videos.

### 1) Type-Locking Rules
- For muapi outputs, enforce explicit `video_type` intent in compiled prompt instructions.
- Add hard constraints per mode (subway/street/studio/wisdom/motivational) so planning cannot drift into mismatched visual grammar.
- Validate selected strategy against chosen mode before enabling generate.

### 2) Cinematic Baseline Rules (All Modes)
- Require camera language in prompt (framing, lens feel, motion style, depth cues).
- Require physically plausible lighting directions and mood consistency.
- Require environmental continuity (location details, texture, ambient movement, no synthetic artifacts).
- Explicitly forbid common AI artifacts (plastic skin, warped hands, floating props, unreadable signage, uncanny faces).

### 3) Human-Realism Rules (All Modes)
- Enforce natural micro-expressions, breathing, conversational pacing, and real-world body mechanics.
- Require authentic wardrobe/material descriptions and realistic skin/hair texture cues.
- Disallow over-stylized/CGI/illustrative aesthetics unless explicitly requested.

### 4) Subway-Specific Realism Hardening (Critical)
- Keep existing subway identity constraints from prompt engine (subway environment + interviewer identity/card-mic rules).
- Add muapi planning checks that always include:
  - real transit environment anchors (MTA/line/city cues as appropriate)
  - handheld documentary motion language
  - commuter background behavior and ambient context
  - clear mic-card visibility and prohibition of traditional mics
- Preserve strict subway negatives already in engine and expand with realism negatives (waxy skin, over-clean set, fake extras).

### 5) Prompt QA Gate Before Generation
- Add preflight `PromptQualityCheck` for muapi-generated prompts:
  - `type_match_score`
  - `cinematic_score`
  - `human_realism_score`
  - `subway_authenticity_score` (only for subway mode)
- If score below threshold, auto-rewrite once with stronger constraints before calling generation.
- Surface a concise warning if rewrite still below threshold and block generation only on severe type mismatch.

## Incremental Delivery Milestones
1. **Scaffold**: add `muapi` type, route, create hub card, page shell.
2. **Brainstorm UI**: build and persist structured ideation inputs.
3. **Plan UI**: strategy options + recommendation + selection.
4. **Track A plumbing**: map planning outputs to existing `createClip` + `build-prompt` fields (no API contract changes).
5. **Cinematic/realism hardening**: add quality guardrails + subway authenticity enforcement in muapi prompt compilation.
6. **Prompt QA gate**: implement preflight type/cinematic/human-realism checks + one-pass auto-rewrite.
7. **Track B metadata**: optional muapi metadata forwarding for backend tuning.
8. **QA**: run lint/build/manual smoke on all existing modes and new muapi flow.

## Test Plan
- Unit-level:
  - muapi type compatibility (no TS regression across existing clip modes)
  - plan validation logic
  - prompt mapping logic for selected strategy
  - prompt QA scoring logic (type/cinematic/human-realism/subway authenticity)
- Integration-level:
  - `/create/muapi` loads and navigates wizard steps correctly
  - cannot generate before plan selection
  - generation payload contains mapped planning fields (Track A)
  - optional metadata fields are non-breaking when backend ignores them (Track B)
- Visual quality acceptance tests:
  - sample prompts for each mode stay mode-correct (no cross-mode contamination)
  - subway outputs preserve card-mic identity and documentary subway environment
  - cinematic realism checklist passes (natural motion, plausible lighting, human facial realism)
- Regression:
  - existing `/create/*` pages still compile and function
  - `CreateHubPage` card navigation unchanged for existing modes

## Risks and Mitigations
- **Risk**: Hook bloat in `useClipCreation`.
  - **Mitigation**: keep muapi planning domain state page-local.
- **Risk**: Backend endpoint lacks muapi support at launch.
  - **Mitigation**: feature flag or explicit unsupported state with no silent fallback.
- **Risk**: Users skip planning mentally.
  - **Mitigation**: enforce plan acceptance gate before generate.

## Implementation Notes
- Prefer additive changes and avoid refactoring existing creation pages during first muapi pass.
- Reuse existing components (wizard, summary, status card) to minimize UI inconsistency and risk.
- Keep copy consistent with current design language and tone in create pages.

## Final Product Decision (Confirmed)
- `muapi` is for creating clips via the existing generation pipeline.
- No standalone planning-only product is needed.
- Implementation should focus on embedding Superpowers-style brainstorm/planning steps before generation, then proceeding to normal clip creation.

## Scope Clarification
- Reuse existing app architecture and create flow patterns.
- Avoid introducing an unrelated new product surface; integrate `muapi` directly into current create experience.
- Primary outcome: better planning quality before clip generation, not a separate artifact system.
- Quality gate strictness: **Strict** (confirmed) — block on mode mismatch, run one auto-rewrite pass, and require high cinematic/human-realism quality before generation.
